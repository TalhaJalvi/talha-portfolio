Static vs Runtime Polymorphism in Kotlin: Overloading vs Overriding

Kotlin developers commonly describe function overloading as static or compile-time polymorphism and method overriding as runtime or dynamic polymorphism. The key difference is when the target implementation is selected.

Quick answer: overloading is selected from the function signature at compile time; overriding uses the actual runtime object to choose an implementation.

1. Static Polymorphism: Function Overloading

class Calculator {
    fun add(a: Int, b: Int) = a + b
    fun add(a: Int, b: Int, c: Int) = a + b + c
}

val calc = Calculator()
calc.add(2, 3)
calc.add(2, 3, 4)

The compiler chooses the matching overload from the argument list and types.

2. Runtime Polymorphism: Method Overriding

open class Animal {
    open fun sound() = println("Animal")
}

class Dog : Animal() {
    override fun sound() = println("Bark")
}

val animal: Animal = Dog()
animal.sound() // Bark

The variable is typed as Animal, but the object is a Dog, so the overridden implementation is dispatched at runtime.

4. Interface Example of Runtime Polymorphism

interface Formatter {
    fun format(value: String): String
}

class JsonFormatter : Formatter {
    override fun format(value: String) = "{\"value\":\"$value\"}"
}

class PlainFormatter : Formatter {
    override fun format(value: String) = value
}

Calling code can depend on Formatter while the concrete implementation changes independently.

5. Common Interview Questions

  • What is static polymorphism in Kotlin? The common term for overload selection at compile time.
  • What is runtime polymorphism? Dynamic dispatch of overridden members based on the real object type.
  • Is overloading the same as overriding? No. Overloads have different signatures; overrides replace inherited behavior with the same contract.
  • Do interfaces support runtime polymorphism? Yes. Multiple implementations can be consumed through the same interface type.
