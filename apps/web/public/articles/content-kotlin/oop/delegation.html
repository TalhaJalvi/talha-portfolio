Delegation & Object Declarations in Kotlin

In Kotlin, two advanced features—delegation and object declarations—help you build cleaner, more modular, and maintainable code. Using the analogy of an airplane’s design and control systems, we’ll explore how delegation lets you share behavior, and how object declarations let you create single-instance managers.

1. Why Delegation & Object Declarations Matter

  • Behavior reuse: Imagine different aircraft types (jet, glider, helicopter) reuse lift or propulsion systems—delegation helps you avoid rewriting the same behavior.
  • Separation of concerns: The airplane class focuses on “aircraft”, while delegate classes handle flying, landing gear, propulsion systems.
  • Singleton / global manager: A single FlightControlCenter object governs all flights—object declarations are perfect for that.
  • Cleaner architecture: Composition over deep inheritance hierarchies—makes your code easier to change when new aircraft types appear.
  • Why use Delegation instead of Inheritance?
    Inheritance allows a class to extend only one superclass, which limits flexibility and can lead to the “diamond problem” (ambiguity from multiple parents). Delegation, on the other hand, lets a class reuse functionality from multiple independent classes (interfaces) safely and clearly.

2. Delegation in Kotlin

Delegation is when one class “hands off” part of its responsibilities to another class (delegate). In Kotlin, this works with interfaces and properties using the by keyword.

2.1 Interface Delegation (Airplane Example)

Suppose you have interfaces for flying and moving. You can implement those behaviors once and reuse via delegation.

Delegation Example: Airplane System

In this example, the Airplane class delegates its behaviors — flying and moving — to two separate systems: Flyable and Movable. Kotlin’s by keyword makes delegation easy and eliminates the need for redundant boilerplate code. 


// Define interfaces representing behaviors
interface Flyable {
    fun fly(): String
}

interface Movable {
    fun move(): String
}

// JetFlySystem provides the actual implementation for flying
class JetFlySystem : Flyable {
    override fun fly() = "Jet-style takeoff and high speed ascent"
}

// TurbofanPropulsion provides implementation for ground and air movement
class TurbofanPropulsion : Movable {
    override fun move() = "Turbofan propulsion: taxi, accelerate, lift-off"
}

// Airplane delegates both Flyable and Movable interfaces to respective systems
class Airplane(
    private val flySystem: Flyable,       // delegate object for flying behavior
    private val propulsion: Movable       // delegate object for movement behavior
) : Flyable by flySystem,                 // Kotlin automatically forwards Flyable calls to flySystem
    Movable by propulsion {               // and Movable calls to propulsion
    // No need to implement fly() or move() manually — compiler does it for you!
}

fun main() {
    val plane = Airplane(JetFlySystem(), TurbofanPropulsion())
    
    // These calls are automatically delegated to their respective systems
    println(plane.fly())   // delegates to JetFlySystem.fly()
    println(plane.move())  // delegates to TurbofanPropulsion.move()
}

Output:


Jet-style takeoff and high speed ascent
Turbofan propulsion: taxi, accelerate, lift-off

Explanation

  • Delegation Concept: Kotlin allows a class to delegate interface implementation to another object using the by keyword.
  • Composition Over Inheritance: Instead of inheriting behavior, Airplane composes behavior by combining different components (Flyable and Movable).
  • Automatic Method Forwarding: Kotlin generates all forwarding methods internally — for example, fly() calls are redirected to flySystem.fly() and move() calls to propulsion.move().
  • Flexibility: You can easily change how the airplane behaves by passing different implementations of Flyable or Movable.

Notes

  • Delegation works only with interfaces — you cannot delegate to concrete classes directly.
  • Overrides are still possible: Even if you delegate, you can override specific methods inside the class to customize behavior.
  • Cleaner Code: The by keyword removes the need to manually write boilerplate like override fun fly() = flySystem.fly().
  • Under the hood: Kotlin stores the delegate object as a property and automatically generates all interface methods that forward calls to it.
  • Use Case: Ideal when different systems (like engines, controls, or navigation modules) handle distinct behaviors but should work together in one unified class.

Output:


Jet-style takeoff and high speed ascent
Turbofan propulsion: taxi, accelerate, lift-off

Explanation:

  • Airplane implements both Flyable and Movable by delegating to the provided systems.
  • No need to manually override each method — the compiler generates forwarding code. :contentReference[oaicite:0]{index=0}

2.2 Manual Delegation (Without `by` Keyword)

Sometimes you want to add extra logic around delegation (e.g., logging or safety checks). You can do it manually:


class AirplaneManual(
    private val flySystem: Flyable,
    private val propulsion: Movable
) : Flyable, Movable {

    override fun fly(): String {
        println("Pre-flight check: systems OK")
        val result = flySystem.fly()
        println("Post-flight log: flight completed")
        return result
    }

    override fun move(): String {
        println("Taxi check, wheels down")
        return propulsion.move()
    }
}

fun main() {
    val plane = AirplaneManual(JetFlySystem(), TurbofanPropulsion())
    println(plane.fly())
    println(plane.move())
}

Output:


Pre-flight check: systems OK
Jet-style takeoff and high speed ascent
Post-flight log: flight completed
Taxi check, wheels down
Turbofan propulsion: taxi, accelerate, lift-off

Explanation:

  • You implement the interfaces yourself and forward calls manually (wrapping additional logic).
  • This gives you full control, at the cost of more boilerplate.
  • Using by offers brevity, but manual delegation offers extension points.

3. Property Delegation (Airplane Systems Monitoring)

Delegation also applies to properties — you can delegate how a property’s getter or setter behaves. Imagine monitoring fuel level or landing gear status. 


import kotlin.properties.Delegates

class AircraftSystems {
    var fuelLevel: Int by Delegates.observable(100) { prop, old, new ->
        println("Fuel level changed from \$old% to \$new%")
    }
}

fun main() {
    val systems = AircraftSystems()
    systems.fuelLevel = 90
    systems.fuelLevel = 75
}

Output:


Fuel level changed from 100% to 90%
Fuel level changed from 90% to 75%

Explanation:

  • The property fuelLevel uses a delegate which runs monitoring logic whenever its value changes.
  • Useful for logging, validating, triggering system alerts when fuel drops below threshold.

4. Object Declarations (Flight Control Manager)

In Kotlin, object declarations define a class and its single instance at once. This is perfect for single-point managers in aviation software.

4.1 Singleton Example


object FlightControlCenter {
    init {
        println("FlightControlCenter initialized – monitoring all flights")
    }
    fun registerFlight(flightId: String) {
        println("Flight \$flightId registered")
    }
}

fun main() {
    FlightControlCenter.registerFlight("A123")
    FlightControlCenter.registerFlight("B456")
}

Output:


FlightControlCenter initialized – monitoring all flights
Flight A123 registered
Flight B456 registered

Explanation:

  • The object keyword creates a thread-safe singleton named FlightControlCenter.
  • The init block executes only once—when the object is first accessed.
  • All subsequent calls reuse that single instance.

4.2 Anonymous Object (One-off Flight Handler)

Sometimes you need a one‐time handler—like a temporary flight-monitor object.


val tempHandler = object {
    fun handleEmergency(flightId: String) {
        println("Emergency handler for flight \$flightId activated")
    }
}

fun main() {
    tempHandler.handleEmergency("C789")
}

Use Case: Quick callbacks, event handlers in aviation simulation environments.

5. Real-World Use Cases (Aviation Context)

  • Delegation: Aircraft class delegates lift and propulsion behavior to systems classes rather than inheriting from a monolithic aircraft superclass.
  • Property Delegation: Monitoring aircraft status (fuel, speed, altitude) through observable or custom delegates.
  • Object Declarations: Central management systems such as FlightControlCenter, Logger, MaintenanceScheduler implemented as singletons.

6. Technical Interview Questions

  • What is delegation in Kotlin?
    A design pattern where a class forwards part of its responsibilities to a delegate object (composition over inheritance). :contentReference[oaicite:1]{index=1}
  • How does Kotlin’s by keyword simplify delegation?
    It causes the compiler to generate forwarding methods automatically instead of writing boilerplate. :contentReference[oaicite:2]{index=2}
  • Can you combine automatic delegation and manual overrides?
    Yes — you can delegate most methods using by and override specific ones manually for customization. :contentReference[oaicite:3]{index=3}
  • What is an object declaration in Kotlin?
    It defines a class and its single instance simultaneously — a singleton. Useful for global managers.
  • Are Kotlin singletons thread-safe by default?
    Yes, the initialization of object declarations is thread-safe and happens lazily when first accessed.

7. Key Takeaways

  • Delegation promotes behavior reuse and cleaner architecture.
  • Use `by` keyword for interface and property delegation to reduce boilerplate.
  • Manual delegation is useful when you need extra control or custom logic.
  • Object declarations offer a straightforward singleton pattern with thread-safety.
  • Using these patterns in an aviation-inspired model (airplane systems, flight control) illustrates how real systems can be built modularly.
