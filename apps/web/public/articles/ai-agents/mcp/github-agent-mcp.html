Build a GitHub Agent with MCP

A GitHub-oriented agent can combine read-only repository context with controlled write tools for issues or pull requests.

Start read-only

Expose repository search, file reads, PR metadata, issue lookup, and commit history first. This validates usefulness without granting mutation rights.

Use scoped credentials

A token should have access only to intended repositories and actions. Never give an agent organization-wide admin credentials because it is convenient.

Require review for writes

Creating or editing issues may be low risk; merging PRs, changing protections, or deleting branches is higher risk. Split tools so approval policies can differ.
