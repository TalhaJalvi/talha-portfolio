MCP Security: What Developers Need to Know

MCP connects models to capabilities that may read private data or perform real actions. Security therefore has to exist at every layer: server trust, identity, authorization, tool design, user approval, network boundaries, and downstream services.

Threat model first

Document what the server can access, whose credentials it uses, which tools mutate state, what data can reach the model, and which callers can connect.

Five core controls

  1. Connect only to trusted servers.
  2. Use least-privilege credentials.
  3. Enforce authorization server-side.
  4. Require approval for high-impact actions.
  5. Trace and audit tool use without logging secrets.
Model instructions are not an access-control mechanism. Security decisions must be enforced in code and infrastructure.
