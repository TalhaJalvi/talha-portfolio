Stateless MCP Server Architecture

Stateless protocol does not mean stateless application. It means an MCP request carries enough information to be handled without a required protocol session pinned to one server instance.

State that still exists

  • User/application sessions.
  • Long-running jobs/tasks.
  • Database transactions.
  • Conversation state.
  • Approvals.

Store durable state in systems designed for it. The transport should not become your state database.

MRTR

Multi Round-Trip Requests support input-required workflows without needing an always-open bidirectional session.

Operational benefit: requests can be routed to any healthy compatible instance.
