Using Multiple MCP Servers

Real agents often need more than one server: GitHub, tickets, database, files, and deployment tools. The challenge becomes managing the combined tool surface.

Filter by agent responsibility

A support agent should not receive deployment tools merely because the host is connected to a deployment server. Minimize every agent's visible capability set.

Isolate failures

If one remote server is slow or unavailable, the host should fail that capability cleanly rather than taking down the whole agent runtime.

Track server identity

For logs, approvals, and security prompts, include which server owns the tool. A tool named delete means little without its server context.
