MCP Elicitation

Elicitation is the pattern for obtaining additional user input when a server cannot complete a request with the arguments it already has.

Example

A deployment tool might know the service name but need the user to confirm production deployment. Instead of inventing a default, the interaction can request confirmation.

Multi Round-Trip Requests

In MCP 2026-07-28, server-to-client interactive requests are restructured around Multi Round-Trip Requests. A server can return an input-required result, the client gathers answers, and then retries the original operation with those answers and the request state attached. This preserves stateless transport while supporting interactive workflows.

Safety

Elicitation should not be used to trick users into disclosing secrets. Hosts should clearly present which server is asking, what data is requested, and why.

Use elicitation for missing user decisions or fields, not as a substitute for server-side authorization.
