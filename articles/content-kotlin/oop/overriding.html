Method and Property Overriding in Kotlin: open, override & final

Overriding in Kotlin lets a subclass replace or extend behavior declared by a parent class. Kotlin makes inheritance explicit: classes and members are final by default, so the parent declaration must be marked open and the child implementation must use override.

Quick answer: mark the parent member open, then declare the child member with override. Use super when the override should reuse the parent implementation.

1. Overriding a Method

open class Aircraft {
    open fun status() = println("Aircraft ready")
}

class Jet : Aircraft() {
    override fun status() = println("Jet ready")
}

Without open on the parent function, Kotlin prevents the override at compile time.

2. Extending Parent Behavior with super

open class Aircraft {
    open fun status() = println("Base checks complete")
}

class Jet : Aircraft() {
    override fun status() {
        super.status()
        println("Jet-specific checks complete")
    }
}

This is useful when the base class contains shared behavior that every subclass should retain.

3. Overriding Properties

open class Aircraft {
    open val type: String = "Aircraft"
}

class Jet : Aircraft() {
    override val type: String = "Jet"
}

4. Can a val Be Overridden with a var?

Yes. A parent val promises only a getter, so a child may provide a var with both getter and setter. A parent var cannot be overridden by a val, because that would remove the setter promised by the parent contract.

open class Aircraft {
    open val speed: Int = 100
}

class Jet : Aircraft() {
    override var speed: Int = 120 // Allowed
}

5. Preventing Further Overrides with final

An overridden member remains open to further overrides unless you explicitly mark it final.

open class Parent {
    open fun run() {}
}

open class Child : Parent() {
    final override fun run() {}
}

class GrandChild : Child() {
    // run() cannot be overridden here
}

6. Overriding vs Overloading

ConceptMeaningExample
OverridingSubclass supplies a new implementation of an inherited memberoverride fun status()
OverloadingMultiple functions share a name but have different parameter listsfun add(a:Int) and fun add(a:Int,b:Int)

7. Common Interview Questions

  • Why are Kotlin members not overridable by default? Kotlin chooses final-by-default semantics to make inheritance intentional.
  • Is override optional? No. Kotlin requires it for clarity and compiler safety.
  • Can a val be overridden by a var? Yes.
  • Can a var be overridden by a val? No.
  • How do you call the parent implementation? Use super.memberName() or super.property.

9. Key Takeaways

  • Use open on parent declarations that are intentionally extensible.
  • Use override on every overriding member.
  • Use final override when a child should stop further customization.
  • Overriding is one of the mechanisms behind runtime polymorphism.
