Encapsulation in Kotlin: Access Modifiers, Getters & Setters

Encapsulation in Kotlin means protecting internal state and exposing only the operations other code needs. Kotlin supports this with private, protected, internal, and public, together with property getters and setters.

Quick answer: keep state private when callers should not change it directly, then expose safe methods or restricted setters that preserve the rules of your class.

1. Why Encapsulation Matters

  • Protects state: prevents invalid changes from outside the class.
  • Controls APIs: callers depend on a small, intentional surface.
  • Makes refactoring safer: implementation details can change without breaking callers.
  • Improves maintainability: mutation happens in predictable places.

2. Basic Encapsulation Example

class BankAccount {
    private var balance: Double = 0.0

    fun deposit(amount: Double) {
        if (amount > 0) balance += amount
    }

    fun withdraw(amount: Double): Boolean {
        if (amount <= 0 || amount > balance) return false
        balance -= amount
        return true
    }

    fun currentBalance(): Double = balance
}

balance cannot be assigned from outside the class. Every mutation passes through a method that can validate the operation.

4. Encapsulation with a Private Setter

class DownloadState {
    var progress: Int = 0
        private set

    fun updateProgress(value: Int) {
        progress = value.coerceIn(0, 100)
    }
}

Other classes can read progress, while only DownloadState can assign to it.

5. Custom Getter and Setter

6. Encapsulation vs Abstraction

Encapsulation controls access to state and implementation details. Abstraction presents a simpler contract while hiding unnecessary complexity. They often work together, but they solve different problems.

7. Common Interview Questions

  • How does Kotlin support encapsulation? Through visibility modifiers, classes, properties, getters, setters, and methods that control mutation.
  • What does private set do? It exposes the property's getter while restricting assignment to the declaring scope.
  • What is internal? It limits a declaration to the same Kotlin module.
  • What is the difference between encapsulation and abstraction? Encapsulation controls access; abstraction hides complexity behind a contract.

9. Key Takeaways

  • Hide mutable implementation details unless callers genuinely need direct access.
  • Use methods and restricted setters to preserve valid state.
  • Use internal for module-level APIs and private for implementation details.
  • Good encapsulation reduces coupling and makes code easier to change safely.
