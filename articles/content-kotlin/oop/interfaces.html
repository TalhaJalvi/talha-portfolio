Kotlin Interfaces & Default Methods: Examples and Conflict Resolution

Kotlin interfaces define a contract that multiple classes can implement. They may declare abstract members and can also provide default method implementations, which makes interfaces useful for reusable behavior without forcing classes into one inheritance hierarchy.

Quick answer: a Kotlin interface can contain methods with bodies. Implementing classes may reuse those default methods or override them. If two interfaces provide the same method signature, the class must resolve the conflict explicitly.

1. Basic Kotlin Interface

interface Flyable {
    fun fly()
}

class Bird : Flyable {
    override fun fly() {
        println("Bird is flying")
    }
}

2. Kotlin Interface Default Method

A method with a body provides a default implementation:

interface Movable {
    fun move() {
        println("Default movement")
    }
}

class Car : Movable // Uses default move()

class Bike : Movable {
    override fun move() {
        println("Bike moves differently")
    }
}

This is the pattern behind searches such as Kotlin interface default method: the implementing class does not need to override a method that already has an implementation.

3. Interface Properties

Interfaces can declare properties, but they cannot own backing fields. A property can be abstract or computed from a getter.

interface Flyer {
    val speed: Int
        get() = 100
}

class Jet : Flyer

4. Multiple Interfaces and Method Conflicts

If two interfaces provide the same member, Kotlin requires the implementing class to choose how the conflict is resolved.

interface Flyer {
    fun action() = println("Flying")
}

interface Mover {
    fun action() = println("Moving")
}

class Drone : Flyer, Mover {
    override fun action() {
        super<Flyer>.action()
        super<Mover>.action()
    }
}

The super<Interface> syntax selects a specific inherited implementation.

6. Practical Architecture Example

interface AnalyticsTracker {
    fun track(event: String)
}

class FirebaseTracker : AnalyticsTracker {
    override fun track(event: String) {
        println("Firebase: $event")
    }
}

class NoOpTracker : AnalyticsTracker {
    override fun track(event: String) = Unit
}

Calling code can depend on AnalyticsTracker instead of one concrete implementation, which reduces coupling and supports testing.

7. Common Interview Questions

  • Can Kotlin interfaces have default methods? Yes. Any interface method with a body is a default implementation.
  • Can an interface store state? It cannot have backing fields, though it may define abstract or computed properties.
  • How are conflicting default methods resolved? Override the member and use super<InterfaceName> when you need a particular parent implementation.
  • Why choose an interface over an abstract class? Interfaces work well for capabilities and multiple contracts; abstract classes are useful when related types also need shared state or construction logic.
