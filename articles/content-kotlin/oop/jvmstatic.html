@JvmStatic in Kotlin: Java Interop, Companion Objects & Examples

@JvmStatic tells the Kotlin compiler to generate a Java-friendly static bridge for a function or property accessor declared in an object or companion object. It is useful when Java callers should use ClassName.method() instead of going through ClassName.Companion.method().

Quick answer: use @JvmStatic for APIs that need natural static-style access from Java. Kotlin callers usually do not need the annotation.

1. Without @JvmStatic

class Utils {
    companion object {
        fun greet(name: String) = "Hello, $name"
    }
}

Java accesses the companion object explicitly:

System.out.println(Utils.Companion.greet("Talha"));

2. With @JvmStatic

class Utils {
    companion object {
        @JvmStatic
        fun greet(name: String) = "Hello, $name"
    }
}

Java can now call:

System.out.println(Utils.greet("Talha"));

Kotlin code can still use the member normally through the class name.

3. Where Can @JvmStatic Be Used?

  • Functions inside a companion object.
  • Functions inside a named or anonymous Kotlin object.
  • Properties in those scopes, where Java-friendly static accessors are generated.

4. @JvmStatic vs @JvmField vs @JvmOverloads

AnnotationWhat it changes for Java callersTypical use
@JvmStaticGenerates static-style method/property accessorsCompanion/object APIs called from Java
@JvmFieldExposes a property as a Java field without getter/setter methodsConstants or direct field interoperability
@JvmOverloadsGenerates Java overloads for default parametersJava-friendly APIs with optional arguments

5. Property Example

class Config {
    companion object {
        @JvmStatic
        val version = "1.0"
    }
}

Java reads this through the generated static getter, for example Config.getVersion(). If you specifically want a field instead of an accessor, look at @JvmField.

6. When Should You Use @JvmStatic?

  • When a Kotlin library exposes companion/object APIs to Java consumers.
  • When migrating a mixed Java/Kotlin codebase and Java call sites expect static-style syntax.
  • When a Java framework expects a static method shape.

Do not add it everywhere by default. If the API is only consumed from Kotlin, it usually adds no benefit.

7. Common Interview Questions

  • What does @JvmStatic do? It generates static bridge methods or accessors for Java interoperability.
  • Does Kotlin have Java's static keyword? No. Kotlin commonly uses top-level declarations, objects, and companion objects instead.
  • Is @JvmStatic required for Kotlin callers? No. Its main purpose is JVM/Java interoperability.
  • What is the difference between @JvmStatic and @JvmField? @JvmStatic gives Java static-style methods/accessors; @JvmField exposes the property as a field.

9. Key Takeaways

  • @JvmStatic is mainly about making Kotlin APIs convenient for Java callers.
  • It is typically used inside objects and companion objects.
  • Use @JvmField when Java needs a field rather than an accessor.
  • Prefer top-level functions when a function does not logically belong to a class.
